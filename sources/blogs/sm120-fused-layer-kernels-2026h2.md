# SM120 fused layer kernels (2026 H2 digest)

Beyond GEMM/attention/MoE building blocks, FlashInfer added large fused SM120 operators (many
generated by NVIDIA's "Cake" generator for MiniMax-H3 diffusion and DeepSeek), a native SM120 GDN
(gated delta rule) prefill, MiniMax Sparse Attention for SM12x, and comm kernels. They contain several
hardware facts that matter for hand-written SM120 kernels.

## Key hardware fact: FP8 MMA issue rate on GeForce vs RTX PRO
- flashinfer#6169 / #6475: on **GeForce GB202 (RTX 5090), dense FP8 `mma.sync ... m16n8k32 .e4m3.e4m3.f32` runs at half rate with an FP32 accumulator** (1024 vs 2048 FLOP/clk/SM). Issuing the same MMA as `kind::mxf8f6f4` block-scaled with **unit UE8M0 scales (every scale byte 0x7F = 2^0)** keeps FP32 accumulation at full rate and is bitwise identical. The host picks the form per device on first call (`cudaDeviceProp::name` contains "GeForce" -> `mxf8f6f4` form). RTX PRO 6000 issues the legacy form at full rate and measured faster with it, so it keeps it.

## flashinfer#5521 / #6475 - MiniMax-H3 fused quantized FC1 + SwiGLU
- #5521 merged 2026-09-25. https://github.com/flashinfer-ai/flashinfer/pull/5521
- RMSNorm + indexed AdaLN + activation quantization + FC1 (5376 -> 28672) + SwiGLU in 2 launches, BF16 [M, 14336] out; FP8 (per-token x per-channel) or NVFP4 (block-16 UE4M3, `alpha = 1/(g_a*g_w)`).
- Design:
  - Persistent 128x128 output tiles over **256 interleaved weight rows: 8 gate rows, then their 8 up rows**. Each thread's mma accumulator fragment then holds the gate/up pair of the same output element, so SwiGLU runs in registers.
  - Operands arrive through a TMA ring with 64-byte rows.
  - **8 MMA warps, with the TMA producer folded into warp 0.** A 9th warp would cap each thread at 168 registers on GB202 and spill.
  - MMA instructions: `kind::f8f6f4 m16n8k32` for FP8, `kind::mxf4nvf4.block_scale m16n8k64` for NVFP4.
- RTX PRO 6000 NVFP4: M=33472 7.65 ms, **1348 TFLOPS**, 1.53x vs segmented chain (norm + quant + `mm_fp4` + `silu_and_mul`), peak memory 1.8 vs 3.9 GiB.
- #6475 (2026-10-14): FP8 raster group 64 (was 16); NVFP4 **producer-warpgroup form (384 threads: 8 mma.sync warps + dedicated TMA producer warpgroup)** replaces the folded producer; GeForce gets the unit-scale mxf8f6f4 FP8 form. Bitwise identical.

## flashinfer#6169 / #6196 - fused full MLP (FC1 + SwiGLU + FC2 + gated residual)
- #6169 merged 2026-10-07. https://github.com/flashinfer-ai/flashinfer/pull/6169
- Three kernels, all `mma.sync` + `ldmatrix` register pipelines: (1) one CTA per row norm/AdaLN/quant; (2) persistent FC1 GEMM with SwiGLU epilogue - NVFP4 variant emits `y` directly as block-16 E2M1 codes + UE4M3 scales so `y` never hits HBM in BF16; (3) persistent FC2 GEMM, **256x128 tiles, K=14336, 4-stage TMA ring**, producer warps quantize `y` per token (FP8), epilogue applies indexed gate and residual. **FC2 M-tile flags order the FC2 producer behind the FC1 tiles of the same rows** (FC1/FC2 overlap without a full grid sync).

## flashinfer#5493 / #5524 - fused pre-attention and output projection
- #5493 (2026-09-23): 2 launches: RMSNorm + AdaLN + quant, then persistent `mma.sync` QKV GEMM 5376 -> 21504 with fused dequant -> BF16 -> Q/K RMSNorm -> 3-D RoPE epilogue writing Q/K/V [M,56,128] as BF16, E4M3 or NVFP4. RTX PRO 6000 (188 SMs): FP8 M=33472 11.79 ms vs 36.59 ms chain (3.10x; bare GEMM 10.66 ms); NVFP4 7.07 vs 27.49 ms (3.89x). https://github.com/flashinfer-ai/flashinfer/pull/5493
- #5524 (2026-09-25): output projection with indexed gate + residual fused.

## flashinfer#3479 / vllm#55715 / TensorRT-LLM#19376 - SM120 GDN (gated delta rule) prefill
- flashinfer#3479 (2026-06-17): CuTe-DSL delta-rule prefill for SM120 (`delta_rule_sm120.py`). Fully fused scheme limited by parallelism when B*H is small: RTX PRO 6000 Qwen3.5-397B TP8 (2 qk / 8 v heads) 1x65536 5.92 ms vs FLA/Triton 2.63 ms (0.44x); context-parallel scheme followed (#3659). https://github.com/flashinfer-ai/flashinfer/pull/3479
- vllm#55715 (2026-09-08): gate only allowed SM90/SM10x, so SM12x silently ran Triton/FLA on 3 of 4 Qwen3.x layers. GB10, Qwen3.8-27B GDN geometry (16 k heads, 48 v heads, d 128): seqlen 1024 1.166 -> 0.305 ms (3.83x); 8192 9.08 -> 2.01 ms (4.52x). Check `final_state` layout (transpose trap). https://github.com/vllm-project/vllm/pull/55715
- TensorRT-LLM#19376 (2026-09-22): RTX 6K Blackwell, Qwen3.5-4B-FP8 ISL 4K: mean TTFT 264.6 -> 200.1 ms (-24.4%).

## flashinfer#3655 / #4030 / #4345 - MiniMax Sparse Attention (MSA) on SM120/121
- #3655 merged 2026-07-15. https://github.com/flashinfer-ai/flashinfer/pull/3655
- Official MSA kernels are SM10x-only; rebuilt on warp-level `mma.sync`: union-tile sparse prefill, adaptive split-K sparse decode that **fuses away the combine when the grid is already full**; top-k and combine rewritten in CuTe-DSL.
- Indexer `msa_proxy_score` = per-KV-block max of QK^T; NVFP4 indexer reads ~2.3x less K-cache traffic. At decode the proxy score tile is too thin for MMA, so it runs on **CUDA cores, streaming index-K from GMEM to registers**; NVFP4 proxy sizes its KV split to balance SMs.
- #4030 chunked top-k + in-kernel causal offsets; #4345 FP8 index-K / index-Q.

## Comm kernels on SM12x
- flashinfer#3903 (2026-07-28): TRT-LLM fused allreduce enabled on SM12x (has clusters, DSMEM, PDL). Pitfall: widening only the JIT gate would have built the lamport (small-batch) kernel with an **empty body** due to a separate compile-time arch check -> silent garbage. Also fixed lamport buffer pointer packing (all archs). https://github.com/flashinfer-ai/flashinfer/pull/3903
- flashinfer#4870 (2026-09-10): PCIe IPC all-reduce gains a copy-engine plane (`cudaMemcpyAsync` on side streams + monotonic flags): `COPY_ENGINE_RING` (4/8 ranks) and `COPY_ENGINE_ISLAND` (4+4 with one cross-socket exchange); for switchless RTX PRO 6000 hosts (vllm#53576, sglang#34528 opt-in).

## flashinfer#6033 - fused GPT-J RoPE + quantize + paged-insert cache writers (DSv4 NVFP4)
- Merged 2026-10-04. https://github.com/flashinfer-ai/flashinfer/pull/6033
- `cake_dsv4_nvfp4_rope_quantize_insert` covers the sliding-window pool. It applies GPT-J RoPE to Q (with head padding, or in place), then GPT-J RoPE + BF16 rounding + NVFP4 quantize + paged insert of the latent KV.
- `cake_dsv4_nvfp4_kv_rope_quantize_insert` covers the compressed pool (`compress_ratio` 1 or 2) and speculative-context writes.
- The records are byte-identical to `nvfp4_quantize_append_sparse_mla_cache` applied to the BF16-rounded roped rows, so the existing decode/prefill kernels read them unchanged. There are 34 generated variants.
- Motivation: the SM120 DSv4 NVFP4 end-to-end regression in vllm#59725. The unfused NVFP4 path wrote the cache in several passes.

## flashinfer#5129 - expert-sorted buffer for the cuTile BF16 MoE GEMM2 at large M
- Merged 2026-09-22. https://github.com/flashinfer-ai/flashinfer/pull/5129
- RTX PRO 6000, 8192 tokens: GEMM2 reached only 176-204 TFLOPS vs 282-288 for GEMM1 (cuBLAS BF16 on that card is about 409).
- Cause: GEMM2's A operand is one activation row per assignment, read through `ct.gather` with no reuse. At large M the tuner picks tile_k=32, so each gathered row segment is only 64 bytes.
- Fix (`sorted_io=True`): GEMM1 scatters its output tiles into a padded expert-sorted row space, so GEMM2 reads contiguous tiles. The W4A4 path already did this.

## sglang#34019 - fused MHC post+pre on by default for SM12x
- Merged 2026-08-14. https://github.com/sgl-project/sglang/pull/34019
- With the TileLang MHC-pre path disabled on SM120/121, DeepSeek-V4 `hc_pre` fell back to an fp32 `F.linear` of shape [M, 16384] x [16384, 24]. cuBLAS served it with `cutlass_80_simt_sgemm`, i.e. CUDA cores and no tensor cores.
- On 2x DGX Spark (TP=2) that fallback cost 93 calls and 9.54 ms per decode step, about 14% of the step, for a 1.5 MB weight. The fused `mhc_fused_post_pre` path is now the default on SM12x.

## KAI Notes
- On RTX 5090 (GeForce), issue FP8 GEMM MMAs as `kind::mxf8f6f4` block-scaled with UE8M0 scale 0x7F to get full-rate FP32 accumulation; on RTX PRO 6000 the plain e4m3 form is already full rate.
- For gated MLPs interleave gate/up weight rows (8+8) so SwiGLU happens on accumulator registers and only the activated half is stored (or quantized in the epilogue).
- Keep warp count <= 8 MMA warps + producer within the 64K-register file; a 9th full warp dropped the cap to 168 regs and spilled on GB202. Use a producer warpgroup with `setmaxnreg` where possible.
- Chain dependent persistent GEMMs (FC1 -> FC2) with per-M-tile ready flags instead of separate launches or grid syncs.
- When an operator is decode-thin (one query token), skip tensor cores and stream from GMEM to registers on CUDA cores.
- Verify arch gates in both the JIT layer and the compile-time `#if` in headers; mismatch yields empty kernels that "succeed".
